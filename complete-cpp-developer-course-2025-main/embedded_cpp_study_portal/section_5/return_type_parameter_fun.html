Section 5 ⚡ Embedded Relevance: Core Return Types Pure Functions [[nodiscard]] Side Effects Idempotence

Void Functions, In-Out Side Effects vs Pure Functions & [[nodiscard]]

Executive Summary: Exploring return types and function side effects. We examine pure functions vs state-mutating functions and demonstrate how the [[nodiscard]] attribute prevents bugs by enforcing inspection of status returns.

💻 1. Annotated Source Code 

#include <iostream>
using namespace std;

void printHello();
void printNumber(int a);
int giveMe10();
int addThese(int num1, int num2);

int square(int n);

int main() {

	int num1 = 120;
	int num2 = 580;

	printHello();
	printNumber(100);

	int someData = giveMe10();
	cout << someData << endl;

	int totalValue = addThese(num1, num2);
	cout << totalValue << endl;

	printNumber(addThese(num1, 50));

	cout << square(7) << endl;

	return 0;
}

void printHello() {
	cout << "Hello there!" << endl;
}

void printNumber(int a) {
	cout << "The number is " << a << endl;
}

int giveMe10() {
	return 10;
}

int addThese(int num1, int num2) {
	return num1 + num2;
}

int square(int n) {
	return n * n;
}

📚 2. Core C++ Concepts Deep-Dive

1. Pure Functions vs Side Effects

  • Pure Functions: Given the same arguments, always return the same result without modifying global state or hardware.
  • Side-Effecting Functions: Mutate global variables, modify parameters, or access hardware I/O registers.

⚡ 3. Embedded Systems & Hardware Reality

1. The [[nodiscard]] Attribute

In firmware, functions returning error codes or hardware ACK statuses must not be ignored. Marking them [[nodiscard]] forces the compiler to flag ignored return values as errors.

💡 4. Production-Ready Embedded Refactoring

Enforcing error code checking with [[nodiscard]]:

#include <cstdint>

enum class SpiStatus : uint8_t { Ok = 0, Busy, Timeout, WriteCollision };

[[nodiscard]] SpiStatus transmitByte(uint8_t byte) noexcept {
    // Write to SPI Data Register...
    return SpiStatus::Ok;

📝 Knowledge Verification Quiz

Q1. What is a 'pure function' in software architecture?
A A function whose return value depends solely on its input arguments with zero observable side effects on external state or hardware
B A function written in assembly language
C A function with no return type
D A function that runs in interrupt context
Detailed Explanation: Pure functions depend only on inputs and cause no side effects (no global writes, no I/O), making them trivial to test and optimize.
Q2. What compile-time protection does [[nodiscard]] provide when placed on a function?
A It emits a compiler warning/error if the caller calls the function without storing or inspecting its return value
B It prevents the function from returning null
C It makes the function execute faster
D It moves the function to Flash memory
Detailed Explanation: [[nodiscard]] alerts the developer if a return value (like a status code) is discarded, preventing unhandled error bugs.
Q3. Why is managing function side effects critical in concurrent RTOS tasks?
A Uncontrolled side effects on shared global variables create race conditions and data corruption without mutex protection
B Side effects delete task stacks
C Side effects lower microcontroller clock speeds
D Side effects disable compiler optimizations
Detailed Explanation: Modifying shared global variables across tasks without synchronization causes race conditions and memory corruption.
Q4. Can the compiler optimize away repeated calls to a pure function with identical arguments?
A Yes, the compiler can memoize or evaluate pure functions at compile time (Common Subexpression Elimination)
B No, every call must execute at runtime
C Only if written in C
D Only on 64-bit systems
Detailed Explanation: Because pure functions have no side effects, compilers can optimize redundant calls through Common Subexpression Elimination.
